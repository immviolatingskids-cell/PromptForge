# PromptForge v0.5.0 — Project Foundations & Reference Model

## Implemented

Projects are local first-class containers stored under `personaforge.projects.v1`. They have stable readable `project_...` IDs, compact metadata, optional shared context (`setting`, `era`, `premise`), workspace metadata, and explicit persona references. Persona JSON is never embedded or mutated by project operations.

The reusable reference model accepts the future object types `persona`, `project`, `cast`, `group`, `relationship`, `location`, and `scene`. It validates references and resolves them to `resolved`, `missing`, or `invalid` without deleting missing targets. Duplicate persona membership is prevented. Removing or deleting a project never deletes personas.

Browser-data export now includes `projects`; import uses collision-safe project IDs and preserves honest missing persona references. Existing persona collision handling remains in `PersonaStore`. Project diagnostics report project/reference totals, resolution states, and duplicate references.

## Audit findings

Existing persona IDs are generated by the generator or copy/variant flows and are stable after save; library metadata stores lineage separately from canonical persona JSON. Persona import remaps collisions and variant parents. Browser data already travels through Control Centre and localStorage. Studio dirty state is owned by `src/app.js`; projects therefore remain downstream storage and do not introduce a second dirty-state system. Hash routing and tabs remain unchanged in this foundation step.

The reusable patterns are localStorage stores, normalized metadata, explicit IDs, collision-safe import, and pure query/diagnostic functions. Persona lineage, canonical normalization, generation state, and dirty Studio behavior remain persona-specific. Project context is not canon and cannot rewrite persona fields. No membership is inferred from names, seeds, tags, lineage, or shared settings.

## Deferred / not supported

Casts, groups, relationships, locations, scenes, contextual overrides, coherence repair, multi-person projection, project dashboards, cloud sync, collaboration, semantic search, and automatic membership inference are intentionally deferred to later v0.5 milestones.
